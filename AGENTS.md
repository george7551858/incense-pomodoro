# AGENTS.md

## Conventions

- **Use English for all code comments and documentation** (including this file, commit messages, and any new docs). UI strings stay in Traditional Chinese.
- Plain static PWA: **no build tooling, no `package.json`, no bundler, no ES modules**. Scripts are classic `<script>` tags loaded in order; keep it that way so the app also works from `file://`.
- Keep `sw.js` and `manifest.webmanifest` at the repo root (the SW scope is its own directory).

## Project layout

```
index.html              Markup only (links css/ and js/)
css/style.css           All styles: paper background, sunlit window light, UI, night theme
js/scene.js             IncenseScene — Canvas renderer (smoke, stick, ember). No timer/UI state.
js/app.js               App logic: timer state, localStorage, UI wiring, console debug API
                        (`window.incense`), Service Worker registration
assets/leaves.png       Leaf-shadow texture for the window-light effect
icons/                  PWA / favicon icons (generated by tools/gen_icons.py)
sw.js                   Service Worker (offline-first cache; see below)
manifest.webmanifest    Web App Manifest
tools/stamp-sw.sh       Stamps a UTC timestamp into the SW `VERSION`
tools/gen_icons.py      Regenerates icons/ (requires Pillow)
```

Load order matters: `js/scene.js` defines the global `IncenseScene` that `js/app.js` uses.

## Window-light effect (`#sunlight`) — rendering pitfalls

Structure: `.glow` / `.glow-bounce` (soft-light washes) → `.shade` (flat group, holds the opacity) → `.wind` (SVG `#wind` displacement filter, screen space) → `.perspective` (matrix3d projection) → `.leaves`; a second `.perspective` holds the blinds; `.progressive-blur` sits on top.

- **Never put a `filter` (e.g. `url(#wind)`) on an element inside `.perspective`.** The matrix3d magnifies the leaves enormously near its vanishing line; Firefox clips the filter surface of such content, producing a hard vertical seam that sways with the leaves (viewport > ~1041px). Chrome hides the problem. Filters go on the flat `.wind` wrapper.
- Opacity belongs on `.shade` (not on each `.perspective`) so overlapping leaf/blind shadows do not double-darken.
- Both `.perspective` planes must keep identical geometry, transform, and mask so leaves and blinds line up.
- Always check visual changes in **both Firefox and Chrome**, at widths both below and above 1280px (the `max-width: 1280px` media query changes the perspective width and masks).

## ⚠️ Read before viewing the UI: PWA cache shows stale builds

The Service Worker causes "I changed the code but still see the old screen":

- `VERSION` is a fixed string; the browser only reinstalls the SW and refreshes the cache when the bytes of `sw.js` change.
- Same-origin assets (`css/`, `js/`, etc.) are **cache-first** — if a cached copy exists, the network is never consulted. Navigations are network-first.
- The SW is offline-first, so **even with no http server running, a previously registered SW serves the whole app from cache**.

### Verifying the UI

1. Start an http server first (the SW is not registered on `file://`, but stale cache may linger):

   ```bash
   python3 -m http.server 8000
   ```

2. In DevTools, bypass the SW cache: Application → Service Workers → **Update on reload** + **Bypass for network**; Network → **Disable cache**; if needed **Unregister** + Clear storage, then reload.
3. Headless screenshots are a quick cross-browser check. Use a **fresh, throwaway profile** each time so no old SW is involved (put it under the git-ignored `tmp/`; a snap-packaged Firefox cannot use profiles inside hidden directories):

   ```bash
   mkdir -p tmp/ff-profile
   firefox --headless --no-remote --profile "$PWD/tmp/ff-profile" --window-size=1400,800 \
     --screenshot "$PWD/tmp/ff.png" http://127.0.0.1:8000/
   google-chrome --headless=new --user-data-dir="$PWD/tmp/chrome-profile" --hide-scrollbars \
     --window-size=1400,800 --virtual-time-budget=3000 --screenshot="$PWD/tmp/chrome.png" http://127.0.0.1:8000/
   ```

4. If you still see an old screen, first confirm whether the SW is serving a stale cache. **Do not assume the code change did not take effect.**

### When a change affects the cache

- Adding, removing, or renaming a file the app loads → update the `CORE` list in `sw.js` (a missing entry makes `cache.addAll` fail and the SW never installs).
- After changing any `CORE` file, run this once **before deploying/committing**:

  ```bash
  tools/stamp-sw.sh
  ```

  It writes the current UTC timestamp into `sw.js` `VERSION` (e.g. `incense-pomodoro-20260618T082415Z`), so browsers reinstall the SW and refresh the cache. **Do not leave `VERSION` at a stale value.**
